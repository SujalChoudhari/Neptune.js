# Debug project runtime smoke

From the repository root, run `npm test`. The smoke test boots this project's actual `main.js`, loads the Town's scene and referenced tilemap through `SceneLoader`, verifies the player and tile entities, confirms the safe square contains no hostile slimes, and fails on any `console.error` during startup. It also walks the player through the purple stairs into the dungeon, verifies the four scene-authored slime enemies navigate to and attack the player, exercises the Warden's two-phase boss behavior, and returns to town while checking the player is preserved and the destination reused. The test uses a local filesystem-backed fetch adapter and the repository's browser mocks; it does not replace the sample scene or loader with fixtures.

To try the sample interactively in a browser, start a static server from the repository root (for example, `python3 -m http.server 8000`) and open `http://localhost:8000/debug_project/`. Press Play Game to start the canvas runtime; use the arrow keys to move the player. The HTML HUD shows the current area, inventory, equipment, quest progress, pause state, and Warden health/phase. Press E near the Town Guide to read dialogue, start the Slime Trouble quest, and receive a Training Blade. The quest advances as dungeon slimes are defeated. Walk to the purple stairs and press E to enter the dungeon; press U to equip the blade and increase melee damage. Press P to pause or resume the dungeon simulation, S to save dungeon position and progression in browser storage, and L to restore that save. Four slimes navigate the dungeon grid and attack when close. After they fall, the Dungeon Warden engages with aimed projectiles, then switches to a stronger area attack below half health. Press J for a melee slash or K for a ranged bolt, both aimed in the player's last horizontal movement direction. Defeating enemies drops slime gel and grants XP. Press E at the dungeon stairs to return to town.

## Modify the sample

The project is ordinary scene JSON and JavaScript under `debug_project/`; no editor-only format or generated bundle is required. To add another tile-aware slime, duplicate a slime entity in `scenes/demo2.scn` inside the `Gameplay` layer, give it a unique name beginning with `Slime `, choose an unoccupied walkable `transform.pos` within the 20×15 dungeon, and adjust its `Shape` color or size. `DungeonEncounter` discovers every matching entity at runtime (the authored sample includes `Slime Verdant` as a working example); it rejects fewer than three slimes but supports additional ones. Change dialogue and quest setup in `scripts/townGuide.js`, or the boss encounter in `scripts/dungeonEncounter.js`. After editing, run `npm ci && npm test` from the repository root; the real-scene runtime smoke checks that the additional authored enemy is initialized and participates in navigation/combat. Reopen the browser page to play your modified scene.
